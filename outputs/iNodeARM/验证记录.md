- 新增 root LaunchDaemon，固定启动受保护目录中的配套核心；移除 VPN 的 `osascript ... with administrator privileges` 启动分支。Portal 继续以普通用户进程启动。
- 服务通过内核审计令牌和精确签名哈希校验调用应用；应用同时核对服务 root 身份与编译内置哈希，现有界面与核心签名校验继续保留。核心仍在启动后分离权限，账号/验证码及网络协议处理不放入常驻 root 服务。
- 新增安装前检查、服务启用、运行目录重建、固定安装位置、更新停止服务和卸载脚本；提供 `outputs/卸载iNodeARM.command`。不改原版 iNode 服务。
- 同一用户最多一个 VPN 核心，Portal 独立；服务关闭时受限网络子进程响应停止信号、清理路由。验证码等待使用轮询关闭检查，不因轮询超时结束，部分请求跨轮询超时保留并继续限制长度。
- 新增蓝色网络节点图标、原生可编辑绘制脚本、16—1024 像素各尺寸及 ICNS，设置 `CFBundleIconFile`。

### 本轮验证

- ARM64 应用、服务和核心构建成功，Hardened Runtime 本地临时签名检查通过。最终版本 0.5.0，构建号 15。
- Rust 库 21 项与桌面核心 20 项测试通过（共 41 项）；覆盖网络子进程等待验证码不退出、部分请求超时后继续解析，以及既有 Portal 模拟登录/心跳/注销。
- 无界面服务协议四组验证通过：会话路径限制、审计令牌签名验证与错误 UID/哈希拒绝、实际双进程请求响应、超长帧拒绝。
- 六组既有 Swift 双连接状态测试通过，覆盖 VPN/Portal 同时在线、切换保留输入和验证码、凭据隔离、背景失败及独立断开和退出。
- 安装/卸载/构建脚本语法与 LaunchDaemon/应用 plist 检查通过。最终 PKG 解包后应用、服务、核心签名有效，应用哈希与服务配置一致，服务/核心与应用编译内置哈希一致，两份核心字节一致，安装位置不可重定位，卸载工具可执行。
- 图标以文件属性验证 16 和 1024 像素规格及包内 ICNS 引用，不进行视觉或交互验证。
- PKG 未使用 Developer ID Installer 签名，应用和服务未公证。当前提供 `iNode-ARM-0.5.0.pkg`、ZIP 应用包及更新源码归档；VPN 需安装 PKG，单独 ZIP 不安装服务。

## 0.5.2 宽松服务器证书处理（2026-11-03）

- 按用户要求，桌面 SSL VPN 改为与 Windows E0598 已分析路径相近的宽松证书处理：保持 TLS 1.2 及以上加密，允许不受信任/过期的证书及名称不符，不做固定 SHA-256 指纹比对。不声称完全复刻 Windows 所有证书认证配置分支。
- 新增桌面专用兼容会话入口，域查询与认证统一通过它创建会话；验证码、请求、隧道和会话重连沿用同一 TLS 连接策略。普通 CLI 入口原有 CA/指纹处理不变。
- 移除桌面固定指纹策略字段及其已不适用的旧断言。旧凭据中的 pin/trustedPin 字段仅保留解码兼容，不作为 TLS 信任依据；账号、密码、后台服务及核心签名校验不变。
- 版本 0.5.2，构建号 17，生成配套安装包和源码归档。
