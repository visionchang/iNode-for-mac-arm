# iNode for Mac 1.0.1

适用于 Apple Silicon、macOS 13.3 或更新版本。这是独立兼容客户端，不是 H3C 官方版本。

## 安装、更新与卸载

1. 完全退出旧版应用，双击 `iNode-for-Mac-1.0.1.arm64.pkg` 完成安装。安装阶段需要 Mac 管理员授权。
2. 从 `/Applications/iNode for Mac.app` 打开应用。安装包同时安装开机启动的专用后台服务，不会修改原版 iNode 的服务。
3. VPN 连接通过该服务启动核心，不再显示旧版的“允许管理员访问脚本”提示。Portal 继续直接启动普通用户核心。
4. 更新时退出应用，再安装同版本配套的新安装包。应用、服务和核心按签名哈希匹配，仅替换应用可能导致版本不匹配。ZIP 应用包不能单独完成后台服务安装。
5. 若服务被系统禁用，在“系统设置 → 通用 → 登录项与扩展”的后台项目中检查 iNode for Mac，或重新安装。服务缺失或不匹配时应用会明确提示，不自动退回脚本授权。
6. 卸载前退出应用，双击项目 `outputs/卸载 iNode for Mac.command`，按终端提示完成管理员授权；也可在终端执行：

```sh
sudo /Library/PrivilegedHelperTools/local.vision.inode-arm/uninstall.sh
```

卸载会移除本应用和专用服务，保留个人设置、本地保存的凭据及在线记录，不影响原版 iNode。

应用名为 iNode for Mac，小字标注 for Mac · Apple Silicon。安装时会替换本项目旧名称 `iNode ARM.app` 或 `iNode for mac arm.app`，但保留原应用标识和数据目录，因此账号、网关、域和记住密码设置继续沿用。

当前应用及服务采用本地临时签名，安装包未使用 Developer ID Installer 签名，也未经过苹果公证。macOS 可能提示无法验证开发者；这与日常 VPN 的管理员脚本弹窗是两回事。

### 后台服务范围

- 系统服务位于 `/Library/PrivilegedHelperTools/local.vision.inode-arm/`，启动项为 `/Library/LaunchDaemons/local.vision.inode-arm.service.plist`。
- 服务核对连接方的内核审计令牌与精确签名哈希，只允许配套应用请求启动固定路径的核心；用户身份与进程编号从系统读取，不接受客户端指定用户或执行命令。
- 应用也核对服务的 root 身份与编译内置签名哈希。服务不接收账号、密码或验证码。
- 核心启动后立即分离权限：认证、Portal 和隧道数据处理以普通用户身份运行；受限子进程只处理虚拟网卡及路由。
- 每个用户最多一个 VPN 核心，Portal 独立运行；断开、退出、升级或卸载时关闭连接并清理路由。安装、重启后服务恢复及真实网络清理效果仍需用户验收。

## 菜单栏

应用运行时，菜单栏显示网络图标；任一连接在线时图标显示盾牌标记。点击图标可分别查看 Portal 和 SSL VPN 的状态、连接或断开，等待验证码时可直接打开对应页面完成验证。连接操作会打开主窗口，以便填写账号密码、处理验证码或查看错误。菜单中也可以打开主窗口或退出应用；退出会断开两种连接。关闭主窗口后菜单栏入口仍然保留。

## 主界面

Portal 和 SSL VPN 可以同时在线。分别选择连接类型并完成登录即可；连接中、等待验证码或已经在线时，都可以切换类型。切换只更换当前显示页面，保留另一种连接、验证码、输入内容和计时器。连接类型使用两张独立卡片，Portal 在左、SSL VPN 在右；当前选择以蓝色突出，状态标签显示各自的在线、连接中、待验证、失败或未连接状态；在线使用绿色标记。已连接时在网关上方显示连接状态卡片。

点击窗口关闭按钮或按 `Command-W` 只关闭主窗口，应用和当前连接继续运行。点击 Dock 图标或再次打开应用时，窗口显示仍在运行的连接状态。通过菜单“退出 iNode for Mac”或 `Command-Q` 才退出应用并断开连接。

“下线”“断开连接”“取消连接”只控制当前显示的类型；退出应用会关闭两种连接。两者各自使用独立核心进程和通信通道，一方失败不会主动清理另一方的会话。

主页面采用蓝色主题，使用紧凑卡片布局，无整页滚动容器；窗口保留最小高度，并允许按内容增加高度，避免通过隐藏滚动条遮挡内容。直接提供连接类型、网关/服务器、域选择、账号、密码和“记住账号密码”。网关显示地址与端口，例如 `vpn.example.com:3000`；VPN 在内部自动补全 `https://`，旧版保存的完整 HTTPS 地址也会隐藏协议前缀。断开 VPN、Portal 下线及取消连接使用红色操作。标题以大字号 iNode 配合小字号 for Mac · Apple Silicon 排版，右上角时钟按钮打开在线记录，连接设置入口放在 SSL VPN 页面的网关卡片内、VPN 网关标题右侧，用于设置额外内网网段；Portal 页面不显示设置按钮。

鼠标移入地址行后，点击右侧的编辑图标修改网关或 Portal 服务器，点击“完成”应用更改并读取新地址的域列表，点击“取消”放弃更改。编辑期间不能连接或操作域；也可以点击域右侧的刷新按钮重新读取。应用首次打开和切换连接类型时也会读取域列表。域查询不提交账号密码。

## SSL VPN

- 默认网关：通过本机 `GatewayPolicy.json` 中的 `defaultGateway` 配置。主界面仅显示和编辑地址与端口，程序在内部自动补 `https://`。
- 域列表从网关公开客户端接口获取。目前目标网关返回 `duanxin`，列表会跟随实际服务器响应变化。
- 安装后台服务后点击“连接”，再按提示输入图片验证码和短信验证码；正常连接不再通过脚本申请系统授权。
- VPN 按 Windows 原版已分析路径采用宽松服务器证书处理：保留 HTTPS/TLS 加密，但不强制验证证书信任链、有效期和主机名，也不再匹配固定 SHA-256 指纹。域查询、登录、验证码、隧道及重连共用这一策略；服务器更换证书不再需要因此更新客户端。
- 该模式不确认服务器身份，存在连接到冒充网关的风险。修改服务器证书处理不会放宽应用、后台服务和核心之间的本机签名校验。
- 支持 IPv4 TLS 隧道、网关下发的内网路由、额外 CIDR 和会话重连。当前不自动配置 DNS，也没有断线阻断功能。

## Portal

- 默认服务器：通过本机 `GatewayPolicy.json` 中的 `defaultPortalGateway` 配置，默认客户端 transfer 端口为 UDP `50200`。可在地址后填写 `:端口`。
- 当前网络需要能访问该服务器。Portal 不负责建立通往单位网络的 VPN 隧道。
- 使用提供的原版客户端中的 IPv4 Portal v2 协议，实现域查询、账号密码认证、在线心跳和下线。不会创建虚拟网卡、修改系统路由或申请管理员权限。
- 域名称由服务器属性 60/61 的标识与 GBK 中文名称对应解析。当前服务器映射为：`cegn` → 政务外网，`web` → WEB，`portal` → 客户端，`guest` → 二维码。界面展示名称，登录仍使用内部标识。首次使用 Portal 或修改服务器后优先选择服务器提供的“客户端”；已保存的选择会保留。“默认”表示不额外添加域后缀。账号本身已包含 `@域` 时不会重复添加。
- 域查询、登录、心跳和下线的请求沿用同一个客户端编号；与原版一致，响应编号可与请求不同，不用响应编号改写后续请求。继续检查服务器来源地址、报文摘要和当前阶段要求的响应类型。登录目标使用域响应指定的服务器地址和端口。登录等待最长 25 秒，超时会明确提示阶段、目标及收到的响应类型/会话编号，不记录账号密码。
- 在线保持采用登录响应下发的心跳周期（属性 109）和超时窗口（属性 119）。周期为 0 或未提供时不主动发送心跳，不会再按固定 8 秒误断开。启用心跳时使用服务器会话用户名和状态字段，按需重发心跳；只有有效应答才延续在线窗口，超时仍会报错。超时窗口未提供时使用 90 秒。服务器明确下线通知会结束连接。
- 点击“登录”，输入的账号密码仅在点击登录后提交。只有收到成功认证响应才显示已连接；点击“下线”会请求服务器注销。
- 上传的 Portal 客户端版本字段按原版资源转换为 `V7.30-0653`，不使用旧版错误的 `V7.30E0653`。
- 认证错误码按原版解释，代码 1 只表示“认证请求被拒绝”。若服务器属性 115 附带说明，会解析 UTF-8/GBK 并展示识别出的原因类别；不输出可能包含凭据的任意响应原文。未识别原因需要结合管理员认证日志判断，不会自动尝试其他密码、域或编码方式。
- 本版支持基本账号密码流程及原版的密码编码标志（属性 55=1）；按能正常登录的 Mac E0641 与 Windows E0598 共同实现，使用 16 轮、32 位溢出和带符号右移的兼容编码，并附带属性 56 标志；修复了 0.4.1—0.4.3 参考 E0653 时采用不同 64 位运算的问题。该方式最多支持 32 字节密码，超长会直接提示，不会截断后登录。客户端挑战校验、短信、IPv6 等扩展尚不支持；遇到要求这些功能的响应会提示适配错误，不冒报成功。
- 这是旧式 UDP Portal 协议；服务器要求时使用原版的固定密钥密码编码，未要求时使用基本密码属性。这些方式及报文 MD5 校验均不能提供 TLS 等级的机密性或可信服务器身份认证。仅在可信单位网络中使用；Portal 不经过 VPN 的 TLS 连接。

## 在线时长与连接日志

- 主界面操作按钮下方用一行浅灰色小字显示当前连接类型的“本次在线”和“累计”，没有记录时不显示计时行；已结束的成功连接显示“上次在线”。Portal 与 SSL VPN 分别累计，两种连接同时在线时各自计时，不相互覆盖。
- 只有收到真正建立连接的事件才开始在线计时。认证、验证码等待不计入在线时长；VPN 重连期间暂停，重连成功后继续本次累计。关闭窗口不影响连接和计时；断开、下线、失败或退出应用时结束本次记录。
- 右上角时钟入口显示“在线记录”，可筛选全部、Portal、SSL VPN，查看网关、账号、域、发起时间、上线时间、结束时间及连接过程事件。选中左侧记录，在右侧查看详情；“导出记录”将当前筛选结果保存为文本文件。
- 连接日志包含开始连接、核心就绪、验证码/短信等待、认证成功、连接建立、重连、下线、失败类别和退出。日志不保存密码、验证码、Cookie、网络报文或未过滤的服务器/程序错误原文。
- 统计从 0.6.0 开始记录，不会导入原版或旧版未记录的在线时间。累计时长跨应用重启保留，按连接类型汇总，不作为服务器计费依据。
- 本地保留所有连接记录，每次连接保留最多 100 条事件。旧版本此前已清除的记录无法恢复。
- 状态变化时保存记录，进行中的连接每 15 秒保存一次快照。若上次运行被强制结束，下次启动将其标记为“上次运行异常结束”，结束时间与时长以最后一次保存为准，不推算应用关闭期间的在线时间。
- 文件保存在 `~/Library/Application Support/iNode ARM/connection-history.json`，沿用原数据目录以兼容更新。目录权限 0700、文件权限 0600。导出的文本包含账号、网关和时间信息，不含密码或验证码。
- 如果读取失败，原文件不会被覆盖，本次先在内存记录；读取或保存错误会显示在在线记录页。

## 本地记住账号密码

勾选后，认证成功才保存。账号在本机设置中，密码以明文保存在 `~/Library/Application Support/iNode ARM/credentials.json`，目录权限 0700、文件权限 0600；同一用户运行的程序和管理员仍可能读取。

VPN 与 Portal 的配置和密码分别保存、读取和删除。切换到另一个类型不会复用前一个类型的密码。域列表刷新、域选择、修改网关或账号均不再自动清空当前密码，包括已自动填充或随后手动修改的密码。空密码时的本地自动读取仍仅匹配当前网关、域和账号，不自动读取其他身份的已保存密码。

取消“记住账号密码”会删除当前连接类型的已保存凭据。图片和短信验证码不保存。连接成功后保留本次输入的密码，主动下线、断开、取消连接及认证失败均不清空，方便在本次应用运行期间直接重连。这个行为不要求勾选“记住账号密码”；未勾选时不会因此将密码写入本地文件。退出应用时清除本次内存中的密码；下次打开是否自动填充仍由“记住账号密码”决定。

应用不再读写系统钥匙串。旧版钥匙串项目不会自动导入或删除，以免再次触发系统授权。

## 历史验证范围（0.4.6 及此前）

- ARM64 编译和本地 Hardened Runtime 签名检查通过；尚未采用 Developer ID 或苹果公证。
- 六组无窗口 Swift 双连接模型测试通过，覆盖切换保留输入/验证码、两种状态同时在线、凭据隔离、背景失败、独立断开和退出清理。
- 最终核心本地并行进程测试通过：Portal 持续心跳时，另一 VPN 核心启动、停止和启动失败均不影响 Portal；未进行真实单位网的双连接认证。
- 63 项 Rust 功能回归通过，包括Mac E0641 / Windows E0598 密码运算与版本编码对照、GBK 中文域映射、认证拒绝原因解析、固定请求编号、服务器指定登录端口、独立响应编号及登录阶段超时提示。
- 最终普通用户核心到本地模拟 Portal 的完整 IPC 登录/下线流程通过，包括关闭心跳后保持超过旧 8 秒窗口，以及开启心跳时首包丢失、重发、状态更新和下线。
- 账号保存逻辑的六组 Swift 测试通过，包含 VPN / Portal 配置与密码隔离。
- 已使用编译后的 ARM 核心只读获取两个真实服务器的域列表，未提交真实账号、密码或验证码。真实 Portal 登录与单位网连通仍需用户自行验收。
- 按用户要求，不执行可视化交互验证、漏洞扫描或渗透测试。

## 从源码构建

需要 Xcode Command Line Tools、Python 3 和 Rust 1.92.0。运行 `./scripts/build.sh`，生成源码目录旁的 `iNode for Mac.app`；可用 `INODE_BUILD_DIR` 指定缓存位置。脚本构建并签名核心和后台服务，将两者的签名哈希编译进界面，生成各尺寸图标后签名整个应用。运行 `./scripts/package.sh` 可额外生成安装包，将最终应用哈希写入服务配置，固定安装到 `/Applications/iNode for Mac.app`。

VPN 基础代码来自 [VocabVictor/inode-cli](https://github.com/VocabVictor/inode-cli)，MIT 许可，基准提交 `200572a70d0402354a3e3cfa46ecfe9ce0d58b86`。许可证保留在 `vendor/inode-cli/LICENSE` 并随应用打包。Portal 兼容代码根据用户提供的客户端协议线索和指定服务器的公开无凭据响应实现。

本版仅做源码静态核对、编译及打包，未执行测试、启动应用或做可视化交互验证。时长刷新、并行连接统计、关闭窗口后计时、历史筛选与导出、跨重启累计、异常结束标记及改名升级由用户验收。
